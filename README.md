# Industrial Copilot — Margin Engine

**An industrial copilot that computes distance to the failure boundary instead of
predicting the probability of failure.** Every number in every answer is
calculated, traced, and verified — never generated by a language model.

Built on the [UCI AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset).

```
Q: "Why are we seeing more failures at high rotational speeds?"

A: You aren't. Failure rate is 12.17% in the lowest rpm quintile and 2.24% in
   the highest — 5.4× more common at LOW speed. The relationship is U-shaped.

   There IS a real high-speed failure mode, and it isn't overload: every
   high-rpm failure is a power STALL. rpm and torque are inversely coupled
   (r = −0.875) around the 2860 W design point, so high speed means low torque
   (mean 10.6 N·m at 2638 rpm) and power falls below the 3500 W floor.

   ⚠ rotational speed and torque are strongly collinear; differences
     attributed to speed may be driven by torque.

   [evidence: 5 quintiles, n=10,000] [plan#8f3c1a] [kb@1.0.0] [12ms · grammar tier]
```

## Why this is different

The AI4I failure modes are **rules, not patterns**. We transcribed each from the
dataset documentation and scored it against the published labels on all 10,000
rows:

| Mode | Rule | Fires | Labelled | FP | FN |
|---|---|---:|---:|---:|---:|
| HDF | ΔT < 8.6 K **and** rpm < 1380 | 115 | 115 | **0** | **0** |
| PWF | torque·ω < 3500 W **or** > 9000 W | 95 | 95 | **0** | **0** |
| OSF | wear·torque > 11k/12k/13k (L/M/H) | 98 | 98 | **0** | **0** |

**287 of 339 failures are exactly explainable by arithmetic.** Answering *"why
did this fail?"* with a gradient-boosted probability converts a known quantity
into an estimate — and then cannot act on it.

A **margin** is a signed scalar in engineering units (`−1,433 min·N·m past the
overstrain limit`). Three properties follow:

- **It inverts** → the system *prescribes*: "reduce torque 4.2 N·m and every margin returns positive."
- **It's continuous** → the system *forecasts*: 811 healthy rows (8.1%) sit within 2% of a boundary. The failure label sees none of them.
- **It's associative** → the system *scales*: `min()` composes losslessly up a rollup tree.

### Language models are bad at time series. We removed them from the numeric path.

Tokenization destroys numeric magnitude; context windows cannot hold a sensor
stream; arithmetic is approximated. Our answer is structural — **the model never
sees the time series.** It converts intent to a validated plan, and later phrases
a result. Everything between is deterministic arithmetic.

→ [docs/02-TIME-SERIES.md](docs/02-TIME-SERIES.md)

## Architecture

```
┌──────────────────────────────────────────────────────────────────────────┐
│ L1  PLANT      PLC/SCADA · MES · Historian · IoT     [AI4I CSV replay]   │
└────────────────────────────────┬─────────────────────────────────────────┘
                                 │ raw samples
┌────────────────────────────────▼─────────────────────────────────────────┐
│ L2  INGEST & NORMALISE                                                    │
│     dimensional typing · derived physics (ΔT, power, overstrain)          │
│     MARGIN COMPUTATION — 5 signed scalars, stateless, 0.22 µs             │
│     invariant evaluation · synthetic overlays [flagged SYNTHETIC]         │
└────────────────────────────────┬─────────────────────────────────────────┘
                                 │ margins + events
┌────────────────────────────────▼─────────────────────────────────────────┐
│ L3  REASONING CORE                                                        │
│   Knowledge base │ Margin evaluator │ Trajectory forecast │ Setpoint solver│
│   (rules+prov.)  │   DIAGNOSIS      │     ANALYSIS        │  PRESCRIPTION  │
│   ───────────────────────────────────────────────────────────────────────│
│   Analysis IR: validate · compile · execute   →   Evidence bundle         │
│   DuckDB │ ClickHouse │ Flink SQL                 typed + full provenance │
└────────────────────────────────┬─────────────────────────────────────────┘
                                 │ evidence
┌────────────────────────────────▼─────────────────────────────────────────┐
│ L4  ACTION   Copilot chat · Envelope explorer · Alerts · [PLC writeback]  │
└──────────────────────────────────────────────────────────────────────────┘
       Data flows up.  Decisions flow down.  [bracketed] = roadmap.
```

### Request lifecycle

```
question → resolver(session state) → ROUTER ─┬─ plan cache      ~0 ms
                                             ├─ grammar planner ~1 ms
                                             └─ LLM planner   ~400 ms
   → Analysis Plan (JSON)
   → schema validator ──(invalid)──► repair ×1 ──► else refuse
   → typed executor → DuckDB                              <10 ms
   → evidence bundle (slots + units + provenance)
   → narrator (writes {{slot}} refs, never digits)
   → PCN verifier ──(bare numeral)──► REJECT ──► regenerate
   → verified answer + evidence + replay handle
```

### The four gates

| Gate | Doubt | Mechanism |
|---|---|---|
| 1 | Is the question's **premise** true? | Premise verification before answering |
| 2 | Is the **instrument** honest? | Physics invariant monitors |
| 3 | Is the **rule** still valid? | KB calibration monitor |
| 4 | Is every **number** sourced? | Proof-Carrying Numbers (fail-closed) |

A **0.4 K thermocouple drift makes heat-dissipation alerts drop 54%.** A
conventional copilot reports "failures down 54% — good month" while the plant
goes blind. Gate 2 separates sensor drift from process drift with z(ΔT)=40.0 vs
z(rpm)=−22.3. → [docs/06-RELIABILITY.md](docs/06-RELIABILITY.md)

## Setup

**Requirements:** Python 3.11+ (tested on 3.14), ~200 MB disk. No GPU. **No API key required.**

```bash
git clone <repo-url> && cd industrial-copilot
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
```

Place the dataset at `data/ai4i2020.csv` (download from
[UCI](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset)),
then:

```bash
make build          # CSV → DuckDB with physics + margins
make verify         # reproduce every figure in docs/01-DATASET.md
make demo           # scripted walkthrough
```

## Configuration

All settings live in `copilot/config.py`; nothing else reads the environment.

| Variable | Default | Purpose |
|---|---|---|
| `COPILOT_CSV` | `data/ai4i2020.csv` | dataset path |
| `COPILOT_DB` | `data/warehouse.duckdb` | warehouse path |
| `COPILOT_PROVIDER` | `deterministic` | `deterministic` \| `anthropic` \| `cerebras` \| `ollama` |
| `ANTHROPIC_API_KEY` | — | enables the Claude planner/narrator |
| `CEREBRAS_API_KEY` | — | free tier: 30 RPM, 60k TPM, 1M tok/day |
| `COPILOT_PLANNER_MODEL` | `claude-haiku-4-5` | planner model |
| `COPILOT_LLM_NARRATION` | `true` | disable for template narration |

**With no provider configured the system is fully functional and fully
evaluable.** The deterministic grammar planner and template narrator cover the
acceptance criteria; adding a key improves phrasing, not correctness. Graceful
degradation to *less fluent* — never to *wrong* — is a deliberate systems
property.

### Cost

~**$0.0034** per fully-LLM question on Haiku 4.5 with prompt caching ≈ **300
questions per dollar**. A 50-question demo costs ~$0.17. Or run it for **$0** on
the deterministic tier, the Cerebras free tier, or local Ollama.

## Performance

Three figures for three different things — conflating them would overstate the case:

| Measurement | Result |
|---|---|
| Raw margin arithmetic, vectorised | **419 M samples/sec/core** |
| Raw margin arithmetic, per event | **0.22 µs** → 4.6 M/sec/core |
| `evaluate()` returning a margin object | **1.09 µs** → 918 k/sec/core |
| Full stream scorer: robust track + alerting | **~14 µs** → ~72 k/sec/core |
| Requirement, 2,000-machine site @ 1 Hz | 2,000 events/sec |
| **Headroom on one core (full scorer)** | **~36×** |
| Query execution | < 10 ms |

Speed is not the result of optimisation — **there is no model to run at inference
time.** Intelligence lives in the knowledge base, built offline; online is
arithmetic.

## Assumptions (summary)

AI4I has **no timestamps** and **no machine identity**. We overlay a 2-minute
takt from a fixed epoch, and a virtual fleet assigned round-robin within quality
variant. **Every synthetic dimension is tagged `SYNTHETIC` in the semantic layer,
and any answer relying on one says so in the response.**

Full list, including the load-bearing assumption that documented thresholds are
given: [docs/12-ASSUMPTIONS.md](docs/12-ASSUMPTIONS.md).

## Intellectual honesty

Most components are **established practice, not invention** — and that is the
point:

| Component | Precedent |
|---|---|
| Rules as diagnostic core | Model-based diagnosis (Reiter 1987; de Kleer & Williams 1987) |
| Margin as health indicator | Standard PHM construct |
| Time-to-crossing | RUL as first-passage time |
| Semantic layer over raw schema | Snowflake Cortex Analyst: 57% → 78% on BIRD |
| Slot-bound numeric verification | [Proof-Carrying Numbers, arXiv:2509.06902](https://arxiv.org/abs/2509.06902) |

The contribution is the **composition**, plus three pieces for which no prior art
was found: the KB calibration monitor, invariant-based sensor/process
discrimination, and the four-gate epistemic perimeter.

**This is not a better product than Siemens Senseye or Cognite** — they have the
OT connector moat, real sensor modalities, and deployment learning. It is a
better *answer engine* on this dataset, on the axes the brief names, built
against the documented reason **80% of industrial AI projects never leave
pilot**: not algorithm performance, but data quality, integration, and trust.
